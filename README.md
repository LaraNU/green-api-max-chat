# GREEN-API MAX-чат

Веб-чат в стиле [web.max.ru](https://web.max.ru/) для отправки и получения текстовых сообщений MAX через [GREEN-API](https://green-api.com/). Тестовое задание на позицию «Фронтенд-разработчик React».

**Демо:** [ссылка на GitHub Pages](https://laranu.github.io/green-api-max-chat/)

## Статус

Реализован и проверен сквозной сценарий

- вход по `idInstance` + `apiTokenInstance`;
- создание чата по номеру телефона (`CheckAccount`);
- отправка сообщений (`SendMessage`);
- приём ответов через цикл long polling (`ReceiveNotification` → `DeleteNotification`), включая обработку 401/403 (автовыход, если токен перестал быть валиден).

Что можно было бы реализовать: сохранение сессии и списка чатов между перезагрузками (`sessionStorage`/`localStorage`), подгрузка истории (`GetChatHistory`), подсветка непрочитанных чатов, тесты. Из-за этого **сейчас обновление страницы разлогинивает** - это ожидаемо на текущем этапе, не баг.

## Стек

Vite + React 19 + TypeScript (`strict`), CSS Modules. Без UI-библиотек, без стейт-менеджеров, без роутера. Состояние - `useReducer` + свои хуки (`useAuth`, `usePolling`).

## Запуск локально

Понадобятся Node.js 20+ и npm.

1. Клонировать репозиторий и перейти в папку проекта:
   ```bash
   git clone <ссылка на репозиторий>
   cd green-api-max-chat
   ```
2. Установить зависимости:
   ```bash
   npm i
   ```
3. Настроить инстанс GREEN-API - см. раздел [«Настройка инстанса»](#настройка-инстанса) ниже (это нужно сделать один раз в личном кабинете, до первого запуска).
4. Запустить дев-сервер:
   ```bash
   npm run dev
   ```
5. Открыть адрес из вывода команды (обычно `http://localhost:5173`).
6. Ввести `idInstance` и `apiTokenInstance` своего инстанса.

## Настройка инстанса

В личном кабинете GREEN-API у используемого инстанса:

- Инстанс должен быть в состоянии `authorized`.
- **`webhookUrl` должен быть пустым.** Приложение получает сообщения через HTTP API (long polling), а вебхук и HTTP API взаимоисключающие.
- Включено только «Получать уведомления о входящих сообщениях и файлах» (`incomingWebhook: yes`). Остальные уведомления лучше выключить: приложение их не обрабатывает, они только занимают очередь.

`apiUrl` вычисляется из первых 4 цифр `idInstance`: `https://{первые 4 цифры}.api.green-api.com`. Если вход не проходит с корректными данными, сверьтесь с `apiUrl` в личном кабинете.

## Как пользоваться

1. Ввести `idInstance` и `apiTokenInstance`, нажать «Войти».
2. Кнопкой «+» создать чат: ввести номер получателя в любом формате (`8 (910) ...`, `+7910...`), приложение нормализует его само. Если номер не зарегистрирован в MAX, форма покажет ошибку.
3. Написать сообщение: `Enter` отправляет, `Shift+Enter` переносит строку.
4. Ответ собеседника появится слева в течение нескольких секунд.
5. «Выйти» завершает сессию и останавливает фоновый опрос.

## Архитектура

```
src/
├── api/         запросы к GREEN-API, типы ответов, адаптеры в Message, тексты ошибок
├── store/       chatReducer - чистая функция без React
├── hooks/       useAuth, usePolling
├── lib/         нормализация и форматирование номера
└── components/  LoginForm, Sidebar, CreateChatModal, ChatWindow, ui/
```

Зависимости идут в одну сторону: `components → hooks → store / api`.

**Слой `api/`** - единственное место, откуда идут запросы к GREEN-API. Он же приводит входящие уведомления и ответ `SendMessage` к одному внутреннему типу `Message`, поэтому компоненты и reducer не знают о форматах GREEN-API. Тексты ошибок сопоставлены с [документацией](https://green-api.com/v3/docs/api/common-errors/) по HTTP-кодам и состояниям инстанса.

**Состояние** (список чатов, сообщения по чатам, активный чат) живёт в одном `useReducer` в `App`. Reducer отбрасывает сообщения от номеров вне списка чатов и дубли по `idMessage`.

**Приём сообщений** - последовательный `while`-цикл в `usePolling`, а не `setInterval`. `ReceiveNotification` - это long polling: запрос держится открытым до 20 секунд и возвращает одно уведомление или `null`. Параллельные запросы по таймеру дали бы гонки и задвоенные сообщения. Цикл общается с приложением только через стабильный `dispatch`, поэтому не страдает от stale closure. Он останавливается через `AbortController` в cleanup `useEffect`: при двойном монтировании в `StrictMode` дублей нет, проверено.

## Что сознательно не сделано

ТЗ просит «максимально простой интерфейс с минимальным набором функций», поэтому объём ограничен сквозным сценарием. Следующие шаги по приоритету:

1. **Сохранение между перезагрузками:** учётные данные в `sessionStorage`, список чатов в `localStorage` по ключу `idInstance`.
2. **История чата** через `GetChatHistory` при открытии (для MAX - до 5000 сообщений / 3 месяцев) с дедупликацией по `idMessage`.
3. **Подсветка чатов с непрочитанными** сообщениями.
4. **Тесты** `chatReducer` (Vitest): дубли, чужой `chatId`, иммутабельность.

Не планировалось: имена и аватарки собеседников (`GetContactInfo`), список всех чатов аккаунта (`GetChats` - возвращает и служебные чаты), медиа, статусы доставки, поиск.
